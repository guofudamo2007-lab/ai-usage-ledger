## 环境

Windows 11 家庭版 x64，便携 CPython 3.14.6。实机安装的 Codex 桌面版本为 26.1117.4957.0，Codex CLI 为 0.149.0，Antigravity 桌面文件版本为 2.34.0.0，AGY CLI 为 1.5.15。

**最终便携包**为 `release/Meter-1.7-preview-Windows-x64.zip`，11,670,819 字节。SHA-256 为 `142bbc9201b85344eda93679456fa41e3a38bb334de9ac51d2e17550933a9ea7`。已检查 ZIP 完整性与包内程序、界面和说明的工作区字节一致性。以下收尾结果对应此构建。

## 在 Windows 复跑

从仓库根目录运行。前两条只需包内 Python 及系统 Node。构建需要 Windows x64 .NET Framework C# 编译器，浏览器验收脚本使用系统 Python 已安装的 Playwright 与本机 Chrome。虚构账本与浏览器测试临时文件放在项目盘的 `.qa`。脚本仅对自己启动的临时服务发送停止请求。

```powershell
.\runtime\python.exe -B -X utf8 -m unittest discover -s tests
node --test tests/references.test.mjs
py -3.14 -B -X utf8 tools/package.py --archive
py -3.14 -B -X utf8 tools/accept_windows.py
```

## 现场收尾结果（2026-11-24）

在 Windows 11 家庭版 10.0.26200 上，沿用上述客户端版本。真实账本及逐请求证据仅保存于本机验收目录，公共材料只列验证方法与结论。

- **迁移统计**。使用同一份升级前 SQLite 快照，以快照最新已入账事件时间为发生时间上限。对基线、迁移完成、首轮重扫、第二轮扫描四个状态逐 UID 比对，额外以独立 SQL 核对每个指标的合计与非空条数，并与产品总览、每日趋势及入口、厂商和模型、项目分组比较。固定范围内一致。验收期间其他客户端继续写入的数据以独立清单解释。现场发现的来源冲突保留全部证据。
- **新接力**。两个独立 Codex CLI 会话和一个 Antigravity CLI ACP 会话在专用目录依次完成三个阶段。逐一核对原始用量与账本，按同一任务标签筛选。对重复副本、重复刷新及最终 ZIP 两次独立进程启动核对后，总览、明细与 CSV、JSON 导出一致。
- **AGY 生命周期**。同一请求在执行中、收到回合完成响应且客户端仍打开、关闭本次 ACP 客户端后三次均有观测。逐项比对步骤与生成元数据、当前有效值及冲突状态，未观察到这笔请求随时间改数。另在隔离副本，通过最终 ZIP 的实际页面选择了一笔历史冲突的生成观测，再选回步骤观测；核对了有效计数、单条汇总和更正依据。执行中反复修订的分支沿用合成用例。
- **修复**。发生计数矛盾时，Codex 来源诊断显示实际违反的数值约束和字节位置。旧诊断缓存能在原文件未变时重读一次；后续沿用新结果。原始矛盾记录仍留待核对。
- **整机断网**。本机未发现可用的干净 Windows 来宾或已连接的独立测试机。本轮已用包内运行时核实离线样本的预检及两个时区的预期结果。整机断网启动与资源加载仍待在独立机器执行。[步骤与三条虚构样本](干净Windows断网验收.md)

本轮接力使用 CLI。已有的真实归档与多模型历史读取结果可沿用，桌面客户端手动触发归档或切换模型的过程未另行录制。
